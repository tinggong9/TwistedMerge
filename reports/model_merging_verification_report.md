# Model Merging Verification Report

This report is generated by `experiments/model_merging_benchmark.py --mode verification`.

## Exact Command

```bash
<repository-root>/.venv/bin/python experiments/model_merging_benchmark.py --mode verification --datasets mnist --architecture mlp2 --model-counts 3,4 --widths 128 --domain-shifts none --seeds 1000,1001,1002,1003,1004 --epochs 10 --max-train-samples 10000 --max-test-samples 1000 --batch-size 128 --lr 0.001 --optimizer adamw --scheduler cosine --weight-decay 0.0001 --device cpu --alignment-noise-levels 0.05,0.15,0.30 --bootstrap-samples 500
```

## Scope

- Dataset grid: `mnist`.
- Architecture setting: `mlp2`.
- Fixed-N repeated-seed settings: `N in 3,4`, widths `128`, seeds `1000,1001,1002,1003,1004`.
- Training uses `10000` MNIST training samples, `1000` test samples, `10` epochs, optimizer `adamw`, scheduler `cosine`, weight decay `0.0001`, and augmentation `none`.
- Alignment variants include observed activation matching plus controlled injected pairwise permutation noise levels `0.05,0.15,0.30`.
- Multi-layer architectures use layerwise permutation alignment and report cycle score on the primary downstream layer.
- Injected alignment rows are a negative/control intervention: they vary cycle score while reusing the same trained models, so they should not be interpreted as independent evidence that cycle score predicts weight-average degradation.

CIFAR was skipped for the verification grid because the prior smoke run has max individual CIFAR accuracy 0.1328, below the 0.20 threshold requested for non-plumbing claims.

## Interpretation

- The fixed-N observed rows are the relevant repeated-seed check for whether cycle score predicts ordinary weight-average degradation beyond the trivial `N=2` versus `N=3` confound.
- The injected-alignment rows test score sensitivity under controlled pairwise inconsistency, but weight averaging itself does not use alignments. Correlation there is a negative-control diagnostic, not a publishable success claim.
- C2M3-style and Git-Re-Basin-style rows are single-model, capacity-matched merged models in this implementation.
- The TwistedMerge/rank-lift row is a branch ensemble with extra capacity. It must not be described as beating single merged models unless a future capacity-matched comparison is added.
- Claims are marked descriptive unless the corresponding fixed-setting repeated-seed statistics provide enough rows and a bootstrap interval that does not cross zero.

## Forbidden-mechanism search

The audit used the following repository-wide search, excluding no source or experiment files:

```bash
rg -n -i -g '*.py' -g '*.md' -g '*.csv' -g '*.json' -g '*.tex' \
  'target_accuracy_for_method|logits_with_target_accuracy|method-dependent target accurac|signal_for|logits_from_signal|ensemble_upper_bound|ensemble upper bound|labels?[^\\n]{0,80}logits|logits[^\\n]{0,80}labels?' .
```

Findings:

1. `src/controlled_nonabelian_holonomy.py` defines `target_accuracy_for_method` and `logits_with_target_accuracy`. The latter reads the candidate's evaluation labels before constructing predictions.
2. `experiments/controlled_nonabelian_holonomy.py` calls both functions separately for every method and split. Its S3/D4 accuracy, loss, selector, paired-statistic, and accuracy-plot outputs are therefore invalid empirical evidence.
3. The old sequential-quotient implementation from commit `9e743a0fd2cefced2c155e47e64466c23c4c9128` used `signal_for`, `logits_from_signal`, and `metric_row`. Those functions are absent from the current executable pipeline; the historical outputs remain invalid and are already separated by `reports/sequential_quotient_lift_correction_note.md`.
4. The term `ensemble_upper_bound` occurs in 93 source, experiment, test, or report files. It is not by itself evidence of label leakage, but the terminology is unsafe. New artifacts use `ensemble_reference`; the release manifest will not promote the old term.
5. No other live source path was found that uses the two exact target-accuracy helpers. Generic occurrences where labels are passed to metric functions or used to generate a fixed teacher were not classified as leakage without a candidate-specific pre-logit dependency.
